- Preserve the imported Vietcasa TanStack routes, UI modules, and design tokens; this keeps future changes aligned with the source app.
- Use this project’s generated Cloud integration and isolated data rather than the source repository’s environment files; imports must not touch the original app’s users or records.
- Home-screen support is manifest-only with shared head tags in the TanStack root route; no app-shell service worker is needed without an explicit offline request.
- Authenticated navigation uses the existing Sheet primitive below the desktop breakpoint; reuse the same navigation links to preserve role visibility and drawer accessibility.
- Dashboard voucher details reuse RecordForm in read-only mode; viewing records must not introduce new write permissions.
- Keep remainingDebt separate from outstanding/collected chart calculations; form settlement changes must not silently alter existing dashboard aggregates.
- The record form's "DT thuần nhân viên" / "DT thuần công ty" use formEmployeeNet / formCompanyNet (no VAT deduction) while dashboards keep netRevenue / companyRevenue; a formula change on one side must not silently move the other.
- Build the file:// edition separately with TanStack hash history and build-only aliases for local data, root shell, and embedded assets; this preserves the hosted app and reuses its exact screens without a second router framework.
- Run scripts/verify_offline.py against the offline output after building; its filesystem and network-disabled Chromium checks fail closed without changing the hosted build lifecycle.
- HTML downloads share one client-side export lock and fetch a prebuilt standalone template generated by scripts/prepare-offline-template.ts; exporting the hosted SSR HTML would retain server-dependent assets. Export only authorized business snapshots via the app-owned IndexedDB store, never raw browser storage or auth sessions.
